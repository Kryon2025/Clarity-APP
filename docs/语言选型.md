# 深清手机端语言选型

## 结论

选 **Kotlin + Jetpack Compose（Android 原生）**。

- minSdk 26（Android 8.0），targetSdk 35；
- 一套代码覆盖 Android 手机/平板；
- iOS 不做：iOS 不允许第三方深度锁机、无障碍拦截和桌面组件，做“深清手机端”的核心价值不成立。

## 为什么不是网页 / PWA

这是本次最关键的一次修正：上一版选了 TypeScript PWA，但 PWA **无法实现深度锁机**。

| 需求 | Web/PWA | Android 原生 |
| --- | --- | --- |
| 前台应用监听、拦截切应用 | 不可能 | AccessibilityService |
| 全屏覆盖其他应用 / 桌面 / 设置 | 不可能（只能全屏自己） | TYPE_ACCESSIBILITY_OVERLAY |
| 锁 home / recents / 状态栏 | 不可能 | Device Owner + Lock Task |
| 后台倒计时、开机恢复 | 不可靠 | ForegroundService + AlarmManager + BOOT_COMPLETED |
| 桌面组件 | 不支持 | AppWidgetProvider + RemoteViews |
| 系统级权限引导 | 受限 | 原生 Settings Intent |

手机端不是“把桌面网页套个壳”，而是要在 Android 权限模型内做到普通应用能做的最高强度锁机。所以必须原生。

## 为什么是 Kotlin + Compose

- **Kotlin** 是 Android 官方语言，直接调用 AccessibilityService、DevicePolicyManager、WindowManager、AppWidget 等系统 API；
- **Jetpack Compose** 让四档空间、专注全屏、数据、插件、设置保持统一的视觉语言，并与桌面 AppTheme 的 79 个颜色 token 对齐；
- 无跨端运行时（Flutter/React Native）在无障碍服务、悬浮层、Device Owner 上仍要写大量原生桥接；本项目直接用原生最短路径；
- 与桌面/Python 的互通发生在 **HTTP 协议 + JSON 主题包** 层，不需要共享运行时。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| TypeScript PWA / WebView | 无法监听/拦截其他应用，无法锁 home/recents/状态栏，无法做桌面组件；与“深度锁机”目标冲突 |
| Flutter | 跨端 UI 可以，但无障碍/悬浮层/Device Owner/Widget 仍要写 Android 原生插件；引入 Dart 运行时与额外体积 |
| React Native | 同上，且对后台前台服务、系统权限的控制更绕 |
| Kotlin Multiplatform + Compose Multiplatform | iOS 端仍无法实现核心锁机；当前只需要 Android |
| Java + XML | 可行但开发效率低；Compose 与主题 token 的映射更直接 |
| iOS / Swift | 系统不允许第三方 App 锁定其他 App；桌面组件可做，但“深清手机端”核心能力缺失，故不做 |

## 与桌面 / 插件的边界

- 手机端**不执行**桌面 Python/QML 插件；插件通过桥接协议暴露 mobile 摘要/指标，手机原生渲染；
- 主题包 .sqtheme 是跨端 JSON：桌面写 custom_themes（0.18+ 已支持 custom:<id>），手机写 filesDir 并叠加令牌；
- 深度锁机是 Android 专属；桌面 Windows 的锁机能力不要求手机复刻，手机做本机自律 + 桌面状态镜像。
